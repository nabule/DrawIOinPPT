## 1. 这是什么

DrawioPpt 是一个面向 PowerPoint Desktop 的原生插件，用来把 Draw.io / diagrams.net 图形以“可编辑、可回写、尽量跟着 PPT 一起保存”的方式带进演示文稿。当前分支也新增了 Word Desktop 原生插件，Word 版的专门说明见 [Word 插件设计与使用说明](./word-addin.md)。

它解决的核心问题是：

- 在 PPT 中插入 SVG 矢量图，而不是低清晰度截图
- 以后还能继续回到 Draw.io 里修改
- 修改后可以回写到原来的那一个图形，而不是重新手工替换
- 尽量把源 XML 保存在 PPT 内部，减少“图还在、源文件丢了”的情况

建议配合以下文档一起看：

- [安装与联调说明](./installation.md)
- [Word 插件设计与使用说明](./word-addin.md)
- [完整 E2E 测试报告](./e2e-test-report-v1.0.0.md)
- [v1.0.0 发布说明](./release-notes-v1.0.0.md)
- [待优化功能点](./optimization-backlog.md)

## 2. 当前能做什么

当前版本已经可以完成下面这些工作：

- 在当前幻灯片中创建新的 Draw.io 图形
- 以 SVG 形式插入图形，保持矢量显示
- 识别已经由插件管理的图形
- 重新编辑已绑定图形
- 支持桌面版 draw.io / diagrams.net 编辑
- 支持 URL 模式编辑
- 保存后把新的 SVG 和 XML 回写到原图形
- 把源 XML 保存到 `Presentation.CustomXMLParts`
- 兼容旧版保存在 `AlternativeText` 里的数据，并在读取时自动迁移
- 为导出的 SVG 补写 draw.io `content` 元数据
- 记录日志，方便排查 URL 模式和回写失败问题
- Ribbon 已按“创建 / 当前图形 / 工作流 / 信息”重新分组
- 已支持 sidecar `.drawio` 在 `PPT` 保存、另存为和跨机器迁移后自动按当前文档路径重定位

当前仍在持续优化的点：

- SVG 替换后的动画、复杂动作和极少数格式的保真还可以继续加强
- URL 模式是否稳定，仍受目标 URL 的部署方式和 embed 协议支持程度影响
- sidecar `.drawio` 文件已支持在“另存为”和跨机器目录变化后按当前 PPT 路径重定位，缺失 sidecar 时的恢复提示还可以继续优化
- 还没有做批量刷新、批量重新绑定、图形管理列表这类增强功能

## 3. 安装后先做什么

第一次使用时，建议按这个顺序：

1. 确认 PowerPoint 已正常加载插件。
2. 点击插件里的“设置”。
3. 先决定你要用 `桌面版` 还是 `网页地址` 模式。
4. 如果用桌面版，先检查“桌面版路径”。
5. 如果用网页地址，先填写“编辑器地址”，再点“测试地址”。
6. 再决定是否开启“选中图形时自动打开编辑器”。
7. 最后再决定是否保留 sidecar 工作文件。

如果你还没有安装插件，先看 [installation.md](./installation.md)。

## 4. 功能区说明

插件在 PowerPoint 功能区里主要提供这些入口：

- `新建`
  在当前幻灯片插入新的 Draw.io 图形，并根据当前设置进入编辑流程。
- `编辑` 或 `重新编辑`
  打开当前选中的 Draw.io 图形。
- `刷新`
  根据绑定的源内容重新生成当前图形。
- `绑定`
  把一个普通图形纳入 DrawioPpt 管理。
- `清除绑定`
  让当前图形不再受插件管理，但保留它在幻灯片里的显示效果。
- `自动打开`
  开启后，选中已绑定图形时会自动进入编辑。
- `设置`
  打开插件设置窗口。

功能区右侧还会显示状态信息，例如：

- 当前有没有选中图形
- 当前是普通图形还是已识别的 Draw.io 图形
- 当前编辑模式是桌面模式还是 URL 模式
- 当前“编辑”按钮是否会显示为“重新编辑”

## 5. 设置项详解

设置窗口中的每一项都直接影响工作流。下面按实际作用逐项解释。

### 5.1 编辑器模式

界面名称：`编辑器模式`

可选值：

- `桌面版`
- `网页地址`

作用：

- `桌面版` 模式会调用本机安装的 `draw.io.exe` 或 `diagrams.net.exe`
- `网页地址` 模式会在插件内打开一个嵌入式 WebView2 编辑器页，并通过 draw.io embed 协议通信

什么时候选桌面版：

- 你已经安装了 draw.io Desktop
- 你希望本地编辑体验更稳定
- 你处在内网环境，或者不希望依赖外网 URL
- 你更习惯使用 `.drawio` 文件

什么时候选网页地址：

- 你不想安装桌面版 draw.io
- 你有稳定可用的 embed URL
- 你希望接入私有化部署的 diagrams.net 地址

推荐：

- 普通个人使用、企业内网使用，优先试 `桌面版`
- 有明确可用的 embed URL，再考虑 `网页地址`

### 5.2 桌面版路径

界面名称：`桌面版路径`

作用：

- 指向本机 draw.io 或 diagrams.net 的可执行文件
- 只有在 `桌面版` 模式下才会真正使用

填写什么：

- `draw.io.exe`
- `drawio.exe`
- `diagrams.net.exe`

你可以怎么填：

- 手工输入完整路径
- 点击 `浏览...` 手动选择
- 点击 `自动检测` 让插件尝试从注册表和常见安装目录中自动寻找

填错会怎样：

- 新建或编辑时无法启动桌面编辑器
- 插件会提示你先配置桌面编辑器路径

建议：

- 如果你不确定路径，优先点 `自动检测`
- 如果自动检测失败，再用 `浏览...` 手工选择

### 5.3 编辑器地址

界面名称：`编辑器地址`

作用：

- 指定 URL 模式下要打开的 draw.io / diagrams.net embed 页面
- 只有在 `网页地址` 模式下才会真正使用

这个地址需要满足什么条件：

- 支持 draw.io embed 协议
- 能处理 `init / load / save / export` 一类消息
- 如果你使用私有部署地址，需要确认它的 embed 能力与官方兼容

默认值：

- 插件默认会给一个官方 `embed.diagrams.net` 风格的地址作为起点

注意：

- 不是任意 diagrams.net 页面都能直接用
- 地址能打开，不代表一定支持保存回调和导出回调
- 最稳妥的做法是填写后先点 `测试地址`

### 5.4 使用兼容 Microsoft Office 的 SVG 文本标签

界面名称：`使用兼容 Microsoft Office 的 SVG 文本标签`

内部含义：

- 对应设置项 `UseOfficeCompatibleSvgLabels`

作用：

- 主要影响 `网页地址` 模式
- 插件会在 URL 编辑器握手阶段向 draw.io 下发 `{ "simpleLabels": true }`
- 目标是改善 SVG 在 PowerPoint 中缩放时的文字边缘清晰度

什么时候建议开启：

- 基本建议保持开启
- 尤其是 URL 模式下，建议不要关闭

什么时候它不起作用：

- 在 `桌面版` 模式下，插件不会直接改写 draw.io Desktop 自身配置
- 如果你希望桌面模式也有类似效果，需要在桌面版 draw.io 中手工配置 `simpleLabels`

### 5.5 选中图形时自动打开编辑器

界面名称：`选中图形时自动打开编辑器`

内部含义：

- 对应设置项 `AutoOpenOnSelection`

作用：

- 开启后，只要你选中了一个已经绑定的 Draw.io 图形，插件就会尝试直接进入编辑

适合什么场景：

- 你频繁需要“点一下就改”
- 你希望减少功能区点击次数

不适合什么场景：

- 你经常只是想选中图形排版，不想每次都进编辑器
- 你经常在一页里快速切换多个图形

建议：

- 刚开始使用时，建议先关闭
- 熟悉工作流以后，再决定是否开启

补充说明：

- 插件内部有短时间抑制逻辑，避免刚刷新或刚保存完时因为重新选中又立刻重复打开

### 5.6 保存后自动刷新图形

界面名称：`保存后自动刷新图形`

内部含义：

- 对应设置项 `AutoUpdateOnSave`

作用：

- 主要影响 `桌面版` 模式
- 插件会监控关联的 `.drawio` 工作文件
- 当你在桌面编辑器里保存后，插件会尝试自动重新生成并替换 PPT 中的图形

适合什么场景：

- 你希望保存 `.drawio` 后 PPT 自动跟着变

关闭后会怎样：

- 你仍然可以手工点功能区里的 `刷新`
- 只是不会在保存后自动回写

建议：

- 基本建议保持开启
- 如果你怀疑自动刷新干扰了你的操作，再考虑临时关闭

### 5.7 新建或编辑时显示图形信息弹窗

界面名称：`新建或编辑时显示图形信息弹窗`

内部含义：

- 对应设置项 `ShowDiagramInfoDialog`

作用：

- 开启后，新建 Draw.io 图形或重新编辑已有图形时，插件会显示当前图形的信息
- 信息包括图形名称、Diagram ID、编辑模式、PowerPoint 图形名称和 `.drawio` 工作文件路径
- 如果桌面编辑器没有成功启动，新建流程也会在这个弹窗里提示当前只是插入了 SVG 预览

什么时候建议开启：

- 你希望确认当前编辑的是哪个 Draw.io 文件
- 你需要查看 sidecar `.drawio` 工作文件实际保存在哪里
- 你在调试路径迁移、另存为或跨机器移动后的工作文件定位

什么时候可以关闭：

- 你已经熟悉工作流，不希望每次新建或编辑时看到额外提示

默认值：

- 开启

### 5.8 在 PPT 附近保留伴随工作文件

界面名称：`在 PPT 附近保留伴随工作文件`

内部含义：

- 对应设置项 `KeepSidecarFile`

作用：

- 决定插件是否把 `.drawio` 工作文件保存在 PPT 同目录附近

开启时：

- 插件会尝试把 `.drawio` 文件放到 PPT 所在目录下的某个子目录中
- 更适合你希望“PPT 和工作文件一起带走”的场景

关闭时：

- 插件会更倾向于使用系统临时目录
- 对临时演示稿、一次性编辑更方便

什么时候建议开启：

- 你希望长期维护这份 PPT
- 你希望同时保留 `.drawio` 工作文件
- 你需要在 PPT 目录里直接看到相关工作文件

什么时候可以关闭：

- 你不希望目录里多出 sidecar 文件
- 这只是临时演示稿

### 5.9 伴随文件夹

界面名称：`伴随文件夹`

内部含义：

- 对应设置项 `SidecarFolderName`

作用：

- 当“在 PPT 附近保留伴随工作文件”开启时，决定 `.drawio` 文件放在哪个子目录里

默认值：

- `drawio`

举例：

如果你的 PPT 是：

```text
D:\Project\demo.pptx
```

伴随文件夹为：

```text
drawio
```

那么 sidecar 文件通常会类似于：

```text
D:\Project\drawio\demo.图形名称.drawio
```

什么时候需要改：

- 你希望把工作文件放在别的子目录
- 你项目里已经有统一的附件目录命名习惯

什么时候不用改：

- 普通使用直接保留默认值即可

### 5.10 浏览、自动检测、测试地址按钮是什么意思

- `浏览...`
  手工选择 draw.io Desktop 的可执行文件。
- `自动检测`
  让插件从注册表和常见安装路径里查找桌面版编辑器。
- `测试地址`
  不保存设置也可以直接打开 URL 编辑器做一次完整握手验证。
  这个测试会检查是否出现保存回调、导出回调，并把日志路径显示出来。

## 6. 推荐配置

如果你不确定怎么配，可以直接参考下面几套。

### 6.1 最稳妥的本地配置

适合大多数个人和企业内网用户：

- `编辑器模式`：`桌面版`
- `桌面版路径`：使用 `自动检测`
- `使用兼容 Microsoft Office 的 SVG 文本标签`：保持勾选
- `选中图形时自动打开编辑器`：先关闭
- `保存后自动刷新图形`：开启
- `在 PPT 附近保留伴随工作文件`：开启
- `伴随文件夹`：保持默认 `drawio`

### 6.2 最省心的 URL 配置

适合已经有稳定 embed 地址的团队：

- `编辑器模式`：`网页地址`
- `编辑器地址`：填写可用的 embed URL
- `使用兼容 Microsoft Office 的 SVG 文本标签`：开启
- `选中图形时自动打开编辑器`：按个人习惯决定
- `保存后自动刷新图形`：可保持开启
- `在 PPT 附近保留伴随工作文件`：按项目需要决定

做完后务必先点一次 `测试地址`。

### 6.3 临时文档配置

适合快速做演示、不想留下太多 sidecar 文件：

- `编辑器模式`：按实际情况选
- `选中图形时自动打开编辑器`：关闭
- `保存后自动刷新图形`：开启
- `在 PPT 附近保留伴随工作文件`：关闭

## 7. 标准使用流程

下面按最常见操作来说明。

### 7.1 新建一个 Draw.io 图形

1. 打开一个 PowerPoint 演示文稿。
2. 切到插件功能区。
3. 点击 `新建`。
4. 插件会先在当前幻灯片插入一个 SVG 图形。
5. 然后根据当前编辑模式：
   - `桌面版`：尝试打开本地 draw.io
   - `网页地址`：打开内嵌 URL 编辑器
6. 在编辑器里保存后，图形会回写到当前 PPT。

补充说明：

- 如果当前是桌面模式，但桌面版路径未配置好，图形会先以预览形式插入
- 如果当前 PPT 还没有先保存到磁盘，而你又开启了 sidecar，插件会先把 `.drawio` 工作文件放到系统临时目录，避免生成无效相对路径
- 当前 PPT 后续一旦保存到正式路径，插件下次编辑时会把 sidecar 自动切换到当前 PPT 同目录下的伴随文件夹
- 如果 `新建或编辑时显示图形信息弹窗` 开启，插件会显示 Diagram ID、编辑模式和 `.drawio` 工作文件路径等信息

### 7.2 重新编辑已有图形

方法一：

1. 选中一个已经由插件管理的图形。
2. 点击 `编辑` 或 `重新编辑`。

方法二：

1. 直接双击已绑定图形。

方法三：

1. 开启 `选中图形时自动打开编辑器`
2. 以后只要选中已绑定图形，就会自动进入编辑

补充说明：

- 如果 `新建或编辑时显示图形信息弹窗` 开启，成功进入编辑流程后会显示当前图形的 Diagram ID、编辑模式和 `.drawio` 工作文件路径

### 7.3 刷新图形

适合这种情况：

- 你在桌面版 draw.io 里已经保存了 `.drawio`
- 但当前这一轮没有自动回写成功
- 或者你想手工确认一次刷新

操作：

1. 选中该图形。
2. 点击 `刷新`。

### 7.4 绑定普通图形

适合这种情况：

- 当前选中的图形还不是 DrawioPpt 创建的
- 但你希望它以后也能纳入插件管理

操作：

1. 选中一个普通图形。
2. 点击 `绑定`。
3. 插件会为它写入 Draw.io 元数据和内部标识。

注意：

- 绑定本身不会自动把这个普通图形变成真正由 draw.io 导出的 SVG
- 更准确地说，这是把当前图形纳入插件的元数据管理体系

### 7.5 清除绑定

操作：

1. 选中一个已绑定图形。
2. 点击 `清除绑定`。

结果：

- 图形会继续留在幻灯片里
- 但插件会移除它的绑定信息
- 后续它就不再被识别为 Draw.io 图形

适合：

- 你想保留显示，但不想继续让插件接管它

## 8. Desktop 模式和 URL 模式的区别

### 8.1 Desktop 模式

优点：

- 本地编辑体验通常更稳定
- 更适合企业内网或离线环境
- 更适合长期维护 `.drawio` 工作文件

工作方式：

- 插件会准备一个 `.drawio` 文件
- 调起本机 draw.io Desktop
- 你保存后，插件监控该文件变化并尝试自动刷新 PPT 图形

你需要知道的事：

- 必须配置有效的桌面版路径
- 如果开启 sidecar，`.drawio` 文件会尽量跟随 PPT 一起存放
- 如果 PPT 尚未保存，sidecar 会先落到系统临时目录
- 如果 PPT 已另存为、移动目录或换到另一台机器，插件会在再次编辑时优先重建到当前 PPT 路径
- 如果希望桌面模式也优化 SVG 文本缩放清晰度，需要在桌面版 draw.io 里手工设置 `simpleLabels`

### 8.2 URL 模式

优点：

- 不依赖本地桌面版 draw.io
- 更容易接入私有部署地址
- 可以通过 `测试地址` 先做自检

工作方式：

- 插件在内部打开 WebView2
- 用嵌入式页面与 draw.io embed 协议通信
- 保存时拿回 XML 和 SVG，再回写到图形

你需要知道的事：

- `编辑器地址` 必须是支持 embed 协议的地址
- 网络、代理、证书、私有部署差异都可能影响握手
- 当前插件会在 URL 模式下自动注入 `simpleLabels`

## 9. 数据保存方式

插件当前采用的是“多层保存”策略。

简单说：Draw.io 源 XML 当前已经保存进 `.pptx` 文件内部。外部 `.drawio` 文件仍可保留，但它主要用于桌面版编辑器打开、人工备份和自动刷新，不再是唯一的数据来源。

### 9.1 PPT 内部主存储

主要源数据会写到：

- `Presentation.CustomXMLParts`

这是最重要的一层，目的是让源 XML 尽量跟着 PPT 文件本身走。

插件写入的是一个自定义 envelope，里面包含：

- `diagramId`
- 图形显示名称
- 当前编辑模式
- 编辑目标，可能是桌面程序路径或 URL
- sidecar `.drawio` 路径
- 更新时间
- 压缩后的 Draw.io XML

Draw.io XML 会先做 `gzip + base64`，再放进 envelope 的 `drawioXml` 节点。这样 PPT 文件会稍微变大，但不会依赖你旁边一定存在某个 `.drawio` 文件。

### 9.2 图形上的引用信息

图形自身会保留：

- `Shape.Tags`

这里主要用于保存：

- `DRAWIO_PPT_ID`
- `DRAWIO_PPT_PART_ID`

它们帮助插件把当前图形和文档级 XML 对应起来。

重新编辑时，插件会先从当前选中的图形读取 `DRAWIO_PPT_ID` / `DRAWIO_PPT_PART_ID`，然后去 `Presentation.CustomXMLParts` 里找完整源 XML。找到后会临时交给 URL 编辑器或桌面 draw.io，保存后再更新 SVG 和文档级 XML。

### 9.3 兼容回退

插件仍然兼容：

- `Shape.AlternativeText`

如果遇到旧版图形只把源数据放在这里，插件会尽量在再次读取时自动迁移到 `CustomXMLParts`。

这一层也用于恢复一些边界场景，例如只复制单个图形到另一个 PPT 时，Office 不一定会同时复制文档级 `CustomXMLParts`。这时图形自身的 `AlternativeText` 和 SVG 内的 draw.io `content` 仍可能帮助插件恢复源数据。

### 9.4 sidecar `.drawio` 工作文件

如果你开启了 sidecar，插件还会在磁盘上保留一个 `.drawio` 文件，方便：

- 桌面版编辑器直接打开
- 你手工查看或备份工作文件
- 在桌面模式下通过文件变化触发自动刷新

需要注意：sidecar 是编辑缓存和人工备份，不是当前实现的主存储。PPT 另存为、移动目录或换机器后，插件会优先使用 PPT 内部的源 XML；如果需要再次进入桌面版 draw.io，再按当前 PPT 路径重建或重定位 sidecar。

### 9.5 SVG 文件中的额外信息

插件生成的 SVG 还会补写 draw.io `content` 元数据，这样单个 SVG 文件本身也会带一份可恢复信息。

这不是主存储，但它让导出的 SVG 本身也更容易排查和恢复。当前插件的主恢复顺序可以理解为：

1. `Presentation.CustomXMLParts`
2. `Shape.Tags` 中的引用信息
3. `Shape.AlternativeText` 兼容回退
4. SVG `content` 元数据
5. sidecar `.drawio` 工作文件

### 9.6 当前没有采用的嵌入方式

当前没有把 `.drawio` 文件作为 OLE 对象或 Office 附件塞进 PPT。这样做的好处是减少 Office 安全提示、文件关联问题和跨机器差异；代价是插件自己维护“图形 ID -> 文档级 XML”的关系。

如果你只是发送一个 `.pptx` 文件给别人，只要对方使用支持本插件的 Office Desktop 环境，源 XML 仍应随 PPT 一起存在。若对方用文档检查器清理自定义 XML、另存为旧格式、导出 PDF，或者用第三方兼容软件重新保存，源数据可能被移除或忽略。

## 10. 日志与排障

默认日志位置：

```text
C:\Users\<你的用户名>\AppData\Roaming\Greensoft\DrawioPpt\Logs\drawioppt.log
```

建议优先看日志的场景：

- URL 编辑器打不开
- URL 地址能打开，但没有保存回调
- URL 保存后没有导出 SVG
- 桌面模式能打开编辑器，但保存后不刷新
- 绑定或清除绑定时提示异常

一个实用的排障顺序是：

1. 先看当前使用的是 `桌面版` 还是 `网页地址`
2. 再检查对应的关键参数有没有填对
3. 然后看日志
4. 最后再做手工重试

## 11. 常见问题

### 11.1 为什么我点了“新建”，但没有进入编辑器

常见原因：

- 你当前是桌面模式，但 `桌面版路径` 不可用
- 你当前是 URL 模式，但 `编辑器地址` 不可用
- URL 页面能打开，但不支持 embed 协议

先检查：

- 桌面模式看 `桌面版路径`
- URL 模式先点 `测试地址`

### 11.2 为什么桌面模式保存了 `.drawio`，PPT 里没更新

先检查：

- `保存后自动刷新图形` 是否开启
- `.drawio` 文件是否真的保存成功
- 日志里有没有刷新异常

如果还是不行：

1. 回到 PPT
2. 选中该图形
3. 手工点一次 `刷新`

### 11.3 为什么 URL 地址能打开，但测试地址还是失败

因为“能打开页面”和“支持 draw.io embed 协议”不是一回事。

`测试地址` 主要检查的是：

- 是否收到 `init`
- 是否能 `load`
- 是否有 `save`
- 是否有 `export`

如果这些回调不完整，页面虽然能开，也不能稳定用于插件工作流。

### 11.4 为什么有时候会看到 `.drawio` 文件在临时目录

通常是因为：

- 当前 PPT 还没先保存到磁盘
- 或者你关闭了 sidecar 保留

这是正常行为，目的是避免对一个还没有真实保存路径的演示文稿生成错误的相对工作文件路径。

补充说明：

- 如果之后你把 PPT 正式保存了，插件会在下一次编辑该图形时把 sidecar 切回当前 PPT 路径附近

### 11.5 为什么 PowerPoint 里文字缩放看起来不够清晰

如果你用的是 URL 模式：

- 保持“使用兼容 Microsoft Office 的 SVG 文本标签”开启

如果你用的是桌面模式：

- 插件不会自动改写桌面版 draw.io 的配置
- 你需要在 draw.io Desktop 里手工启用 `simpleLabels`

### 11.6 清除绑定后，图形是不是会被删除

不会。

清除绑定只会移除插件管理关系，不会删除当前幻灯片上的图形本身。

### 11.7 绑定普通图形后，它是不是就变成真正的 Draw.io 图了

不是完全等价。

“绑定”更像是把当前图形纳入插件管理，并为它建立 Draw.io 元数据关系。后续是否按 Draw.io 方式继续编辑、回写，仍取决于这个图形的源数据是否完整、当前编辑流程是否成功。

## 12. 适合与不适合的使用场景

更适合当前版本的场景：

- 单人维护的 PowerPoint 文档
- 需要把 Draw.io 源数据跟 PPT 一起保存的场景
- PowerPoint Desktop 环境
- 能接受脚本安装和轻量配置的团队

建议谨慎使用的场景：

- 动画和复杂动作非常重的演示文稿
- 多人频繁同时修改同一 PPT
- 需要统一企业级安装器、强管控发布流程的受管环境

## 13. 一个最简单的上手建议

如果你只想先稳定用起来，可以直接这样做：

1. 打开设置
2. 把 `编辑器模式` 设为 `桌面版`
3. 点 `自动检测`
4. 保持 `保存后自动刷新图形` 开启
5. 保持 `在 PPT 附近保留伴随工作文件` 开启
6. 先不要开启 `选中图形时自动打开编辑器`
7. 新建一个图形，保存一次，确认它能正常回写

等这套流程跑顺了，再去尝试 URL 模式和自动打开。
